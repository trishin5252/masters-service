# Сервис поиска мастеров

Приложение для поиска мастеров и управления заказами. Консольная версия ПР3
сохранена, в ПР5 добавлен Django, а в ПР6 веб-страницы перенесены на шаблоны.

## Назначение

Приложение позволяет находить мастеров по специальности, просматривать их профили с рейтингом и опытом работы, а также создавать и управлять заказами на услуги с указанием даты выполнения.

## Целевая аудитория

- Частные клиенты, нуждающиеся в бытовых и профессиональных услугах
- Мастера и специалисты, ищущие заказы
- Владельцы небольших сервисных компаний

## Предметная область

Рынок услуг и сервисного обслуживания. Платформа соединяет заказчиков с исполнителями, обеспечивает поиск мастеров, проверку их доступности и ведение истории заказов.

## Основные сущности

**Мастер** — специалист, оказывающий услуги. Содержит информацию: уникальный идентификатор, ФИО, специальность, опыт работы в годах, рейтинг от 0 до 5, цена за час работы.

**Заказ** — бронирование мастера клиентом. Содержит: уникальный номер заказа, идентификатор мастера, имя клиента, название услуги, дата записи, статус заказа (создан или отменён).

**Пользователь** — клиент сервиса. Пользователи хранятся в `data/users.json` и связываются с заказом через поле `user_id`. Отдельная регистрация и авторизация в рамках этой практической работы не требуются.

**Услуга** — вид работы, который выполняет мастер. Содержит: идентификатор, название услуги, категория (сантехника, электрика и т.д.), примерное время выполнения в часах.

## Основные функции

### Работа с мастерами
- Поиск мастера по уникальному идентификатору
- Поиск мастеров по специальности (поиск по подстроке)
- Фильтрация мастеров по минимальному рейтингу
- Сортировка мастеров по рейтингу (от высокого к низкому)
- Получение текстового описания мастера

### Работа с заказами
- Создание нового заказа
- Поиск всех заказов конкретного мастера
- Отмена заказа по номеру
- Получение текстового статуса заказа
- Проверка доступности мастера на дату

### Работа с пользователями
- Хранение пользователей в JSON-файле
- Поиск пользователя по идентификатору
- Привязка пользователя к заказу

### Работа с данными
- Загрузка данных из JSON-файлов
- Сохранение данных в JSON-файлы
- Обработка ошибок при работе с файлами

### Вспомогательные функции
- Ввод целых чисел с проверкой корректности
- Ввод даты в формате год-месяц-день с проверкой
- Отображение главного меню приложения

## Объектная модель ПР3

Основные сущности проекта представлены классами:

- `Master` в `models/master.py` хранит данные мастера и формирует его строковое представление.
- `User` в `models/user.py` хранит клиента сервиса и умеет преобразовываться в JSON-данные.
- `Order` в `models/order.py` хранит ссылки на объекты `Master`, `User` и `Service`, дату и состояние заказа. Методы `cancel()` и свойство `is_cancelled` управляют состоянием заказа.

Коллекции приложения теперь содержат объекты. Модуль `storage.py` преобразует JSON в объекты при загрузке и объекты обратно в JSON при сохранении. Функции поиска, фильтрации, сортировки и статистики работают с коллекциями объектов.

## Веб-интерфейс ПР6

Django-проект `master_service` использует текущую предметную модель ПР3 и
JSON-файлы. База данных пока нужна только для служебных компонентов Django:
перенос сущностей в Django ORM, формы и авторизация будут добавлены позднее.

### Django-приложения

- `homepage` — главная страница и собственные статические файлы;
- `masters` — список и карточки мастеров, каталог услуг;
- `orders` — список и карточки заказов.

### Шаблоны и отображение

Общий каркас сайта находится в `templates/base.html`, а навигация — в
`templates/includes/navigation.html`. Шаблоны страниц приложений наследуют
`base.html` через `{% extends %}` и переопределяют блоки заголовка и содержимого.
Повторяющиеся карточки мастеров и статусы заказов подключаются через
`{% include %}`. View-функции загружают объекты из JSON, передают их шаблонам
через контекст и вызывают `render()`. Списки выводятся циклом `{% for %}` с
`{% empty %}`, статусы — через `{% if %}`. Фильтры `length`, `default` и `date`
используются для количества записей, отсутствующих значений и дат.

Маршруты имеют имена и пространства имён `homepage`, `masters`, `services`
и `orders`; ссылки в шаблонах строятся тегом `{% url %}`. Собственные CSS,
JavaScript и логотип расположены в `homepage/static/homepage/` и подключены
через `{% static %}`. Скрипт подсвечивает текущий раздел и копирует ссылку на
карточку мастера или заказа. Функция `page()` из ПР5 удалена.

### Страницы

| URL | Назначение |
| --- | --- |
| `/` | главная страница и навигация |
| `/masters/` | список мастеров из `data/masters.json` |
| `/masters/1/` | карточка конкретного мастера |
| `/services/` | каталог услуг из `data/services.json` |
| `/orders/` | список заказов из `data/orders.json` |
| `/orders/1/` | карточка конкретного заказа |

Все страницы используют HTML, Bootstrap 5.3 через CDN и собственный CSS.
View-функции загружают объекты через `storage.py`, а динамические адреса
возвращают HTTP 404, если мастер или заказ с указанным ID не существует.
Предметные модели по-прежнему хранятся в JSON; Django ORM и веб-формы ещё не
используются.

## Завершение ПР3: классы и взаимодействие объектов

| Класс | Атрибуты | Поведение |
| --- | --- | --- |
| `Master` | id, name, specialty, experience, rating, price_per_hour | `meets_rating()`, `__str__()`, `to_dict()`, `from_dict()` |
| `User` | id, name, role, phone | проверка имени, `__str__()`, `to_dict()`, `from_dict()` |
| `Order` | id, master, user, service, booking_date, _status | `cancel()`, свойства `status` и `is_cancelled`, `__str__()`, `to_dict()` |
| `Service` | id, name, category, estimated_hours, master_id, price | `calculate_cost()`, `__str__()`, `to_dict()`, `from_dict()` |

Все классы имеют явный конструктор `__init__`. Заказ хранит ссылки на
существующие объекты мастера, клиента и услуги. В JSON записываются их идентификаторы,
при загрузке ссылки восстанавливаются. Дата заказа в памяти имеет тип `date`.
Активный заказ блокирует мастера на весь день; отмена освобождает дату.
При создании заказа пользователь выбирает услугу по ID из каталога.

Инкапсуляция: статус заказа доступен для чтения через `@property`,
изменение выполняется методом `cancel()`. Полиморфизм: `print()` использует
свой `__str__()` каждого класса. Композиция: `Order` содержит `Master`, `User` и `Service`.
Наследование намеренно не добавлено: клиент, мастер и заказ не являются
разновидностями друг друга. Поиск и сортировка коллекций остались функциями.
Методы `from_dict()` используют `@classmethod` для создания экземпляров из JSON.

### Структура и соответствие ПР2

- `main.py` — меню, выбор объектов, обработка ошибок загрузки и сохранения;
- `models/` — папка с классами `Master`, `User`, `Service`, `Order`;
- `operations/master_actions.py` — поиск, сортировка и фильтрация мастеров;
- `operations/user_actions.py` — добавление и поиск пользователей;
- `operations/order_actions.py` — операции над коллекцией заказов;
- `operations/service_catalog.py` — функции каталога и расчёта стоимости;
- `storage.py` — загрузка JSON, восстановление объектов, сохранение;
- `utils.py` — ввод чисел, рейтинга и дат, меню и справочник;
- `data/` — masters.json, users.json, orders.json, services.json,
  specialties.json (словарь справочной информации);
- `tests/` — адаптированные тесты ПР2 и проверки взаимодействия объектов ПР3.

Пункт 10 добавляет клиента, пункт 11 показывает каталог услуг.
При создании заказа выбирается существующий клиент по ID.
Гостевые заказы старого формата при загрузке получают объект клиента по имени.
Неизвестный ненулевой user_id или отсутствующий мастер останавливают загрузку
с сообщением об ошибке; повреждённый JSON не заменяется пустым списком.
Сохранение каждого файла выполняется через временный файл с последующей заменой.

### Окружение и проверки

Из папки проекта в PowerShell (активация venv необязательна):

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe main.py
.\venv\Scripts\python.exe manage.py check
.\venv\Scripts\python.exe -m pytest -v
.\venv\Scripts\python.exe -m flake8 .
```

Данные ищутся относительно расположения программы, поэтому запуск возможен
из другой папки. Изменения сохраняются пунктом 0 меню.
Тесты работают с временными файлами и не изменяют пользовательские данные.
Материалы Яндекс Практикума в эту доработку не включены.
